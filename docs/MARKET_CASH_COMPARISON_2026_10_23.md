# 現金銷售比較與差額：UX-NEXT-03B

日期：2026-10-23；啟用與雲端驗收更新：2026-10-24。狀態：使用者確認完成 079，本機比較入口已啟用；真實測試 owner 的現金／非現金來源、選填進出與基準保存、獨立來源還原、補登／撤回重算及衝突整合已驗收。正式部署、真正第二台裝置與原生實機尚未驗收。

## 使用方式與金額定義

- 沿用逐場逐日的開／收攤盤點及持久草稿；不增加強制開攤或結帳步驟。
- 展開盤點時才掛載比較功能；從雲端讀取該場完整成交與撤回快照，不以可能缺漏的本機快取或市場總營收取代付款分類。
- 只計明確屬於所選營業日的有效 `deal_closed`，依 `deal_deleted` 的目標 ID 排除原成交；重複撤回不重複扣款，不信任撤回自行填入的金額。
- 現金銷售只含 `cash`；`card`／`mobile` 顯示為排除的非現金。`other`、混合／缺漏／無效付款分類均待確認，不默認非現金。歷史 cash 預設值不被改寫或視為錯誤。
- 使用既有 camelCase／snake_case 金額及日期別名，金額以整數分處理。無效／負成交金額不偷偷歸零；缺少明確有效營業日期的歷史紀錄不以裝置時區推定，列出待確認數量。
- 可選「其他現金進出」一個淨額與備註，預設不記錄。手機以「補入／拿出、支出、退現」方向選擇搭配非負金額欄位，儲存為正負淨額；可明確輸入 0。金額與備註限制沿用 03A。沒有盤點仍可保存明確進出紀錄，缺失盤點不轉成零。
- 預期收攤 = 開攤 + 該日現金銷售 + 其他進出；未記進出時清楚標示「假設沒有其他現金進出」。實盤差額 = 實際收攤 − 預期收攤，多出／短少方向明確。缺開攤或收攤不計差額；負預期收攤提示檢查重複進出。
- 範例：開攤 2,000、現金銷售 3,500、非現金 1,000、收攤 5,450，預期 5,500，短少 50；若另記拿出 50，預期 5,450，差額 0。已記錄營收仍為 4,500，不因比較更動成交、商品、成本、庫存或利潤。

## 完整度與比較基準

- 雲端 RPC 在一個查詢快照讀出全部原成交與 tombstone，包含員工替該品牌記錄的成交；每場上限 10,000 個來源事件，超過明確拒絕，不回傳部分結果冒充完整來源。未額外拉取不相干市集。
- 來源讀取失敗／過期、離線、背景切換、角色待確認、該場本機成交／撤回尚未確認同步、付款／金額／營業日資料缺漏時，顯示待確認與暫估。保留盤點／草稿，但不能記下比較基準。
- 不保證其他裝置沒有尚未送出的成交；畫面列出來源讀取時間與限制。即使差額 0，也只稱「目前記錄相符」，不寫「已對平」或完成全部帳務核對。
- 編輯模式可自願「記下目前比較基準」，與盤點一起明確保存到雲端；不因重連或背景同步代為送出。基準是比較快照，不是認證、結帳鎖或第三方帳務證明。
- 基準保存來源 key、讀取時間與盤點／進出／備註的比較 key。重讀後發現補登、撤回、付款或來源改動，或更正盤點、進出、備註時，提示原基準已更新；重新計算而不沿用先前差額。來源 key 保守涵蓋該場全部成交／撤回，其他營業日改動也可能要求重看。
- 本機成交有變動／同步狀態改變時重讀；網路及前景切換透過既有 platform ports 使讀取狀態失效並重新確認。沒有背景寫入、自動重試 writer、原生 API 或同源 BFF 假設。

## 雲端相容、權限及檔案

- 079 需要已完成的 078。沿用 `market_cash_records`、RLS、revision／mutation ID、CAS 及日別隔離，擴充可選 `data.otherCash`／`data.salesBasis`；沒有新增表、事件或資料批次重寫。
- `save_market_cash_record_v2` 驗證新欄位、原 owner／非刪除場次／日期／版本；相同 mutation 與內容重試冪等。舊 RPC 繼續支援未含新欄位的紀錄，但遇新版紀錄回 `CASH_CLIENT_UPGRADE`，防止舊 client 靜默移除進出或比較基準。
- `read_market_cash_sales` 是 owner-only SECURITY DEFINER RPC，明確驗證登入者等於原場次 owner；manager／operator／viewer 即使可見市集，也無法讀來源或寫盤點。匿名、service_role 及內部 helper 不新增執行授權；不得直接從 client 寫表。讀取與 writer 均有受限請求時間、無自動 writer retry。
- 本機新欄位沿用既有草稿／同步副本，不另加 Dexie table。換帳號／cache reset epoch 拒絕晚到來源，保留原有草稿登出／刪帳號／排程保護；舊財務匯出仍不能當作草稿已保存。
