# UI-11 商品照片狀態與重試

日期：2026-10-27，Asia/Taipei。範圍是商品照片呈現與唯讀回覆；本機實作完成，尚未提交／推送／部署。不是新的照片儲存方案或訂閱制度調整。

## 使用者看到的差異

| 狀態 | 呈現與操作 |
| --- | --- |
| 讀取中 | 精簡載入狀態，不先放大片空白照片框 |
| 已有照片 | 顯示圖片，原有更換／拍照及授權後刪除入口保留 |
| 確定沒有照片 | 啟用時保留加入照片按鈕，省略空白預覽框 |
| 暫時讀取失敗 | 顯示重試；編輯欄位有短說明，清單卡片以具輔助名稱的重試圖示呈現 |
| 照片服務暫停 | 清單只有一則服務狀態與重試；編輯時已有照片或狀態未知者保留精簡說明／重新確認 |
| 未啟用且確定沒有資料 | 新增商品無選圖時隱藏；既有商品必須雲端確認空白、讀完本機待上傳紀錄且確認沒有資料後才整段隱藏 |
| 本機待上傳 | 呈現待上傳狀態；有完整紀錄與payload、具既有管理權限時，可沿原流程重試。紀錄不完整時要求重新選圖，不宣稱原檔一定存在 |

## 資料與權限邊界

- 只有已授權圖片查詢的`404 photo_empty`代表確定空白。舊`404 not_found`、未登入、資料庫／R2失敗與雲端上傳中均視為無法讀取，不視為照片不存在。
- metadata成功必須明確`state: ready`且版本為有效安全整數；失敗／停用不清空同帳號、同owner及角色範圍內已知版本。整批成功的空集合才可清除舊版本。
- 雲端有未完成照片列時，metadata回傳`photo_pending`失敗狀態，避免將其列為確定空白；其他批次成功資料仍可合併。
- 同商品重試失敗保留最後有效圖片；切換商品不沿用前一商品圖片。替換／取消請求／卸載時釋放blob URL，圖片解碼錯誤也有重試。
- 圖片重試使用no-store重新請求。API維持原認證、owner／Team角色與CORS界線；不新增公開圖片網址。
- 沒有新增照片寫入協定、修改待上傳writer／payload清除規則、SQL或放寬訂閱gate。圖片本體仍是Cloudflare R2。
- 共用判斷在`lib/products/product-cover-photo-read.ts`；裝置選圖仍沿既有`lib/platform`，沒有新增原生套件。

## 本輪實際手機畫面複驗

內建瀏覽器，localhost正式App，390×844 CSS尺寸。既有123@123測試帳號，原方案未覆寫；暫切輕量版後只查看既有合成商品，沒有保存商品、選檔、上傳、刪除或新增交易。

1. `[驗收1027-P] 線上封面測試`：本機照片物件讀取失敗呈現重試，點擊後經loading再次回到失敗提示，不假裝沒有照片。照片管理未啟用時保留精簡服務狀態。
2. `[驗收1026-M] 流程測試商品`：雲端確認沒有照片且本機無待上傳，照片管理未啟用時整段照片欄位隱藏，沒有殘留標頭／外框。
3. 暫時啟用本機照片管理UI：已有照片讀取失敗時顯示「照片暫時無法讀取／重試」，仍提供「更換照片／拍照」，沒有顯示可誤刪的照片刪除入口。
4. 暫停本機照片讀取：清單顯示「照片服務目前暫停；商品資料仍可使用。」與重試按鈕，實際按下可重新檢查。
5. `documentElement.clientWidth`與`scrollWidth`皆390，沒有橫向溢出。暫時環境設定已從原檔逐位元還原，測試覆寫已按「還原帳號原有方案」，清除viewport覆寫。

本機R2讀取失敗只用來驗證失敗畫面，未嘗試修改儲存配置；上一輪正式線上上傳／整頁重載成功證據仍保留。這輪不能宣稱新讀取契約已在線上部署，或取代真正staff／iPhone／Android驗收。
