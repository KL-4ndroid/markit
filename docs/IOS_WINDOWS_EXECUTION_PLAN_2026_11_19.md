退出條件是每個仍失敗的檢查都有原因、影響與下一動作，而且下一批可依固定版本開始。

## 驗證與中斷恢復規則

1. 每個驗收批次固定一個可追蹤提交；必要時保留切片檢查點，合併記錄修改、已跑檢查和剩餘事項。
2. 日常採最低必要檢查，按 B01–B06 集中整合驗收；本輪最終候選集中執行一次發布組合。只有程式、環境或新失敗使既有證據失效時，才重跑相關案例。
3. 隔離通過、託管通過、正式發布及 iPhone 通過分別列證據，不以檔案存在推定啟用。
4. 中斷後先讀本表與工作樹，核對上一個命令及遠端結果；不明寫入先查回條，再決定是否重試。
5. 雲端變更集中部署，使用合成帳號驗證；憑證與敏感資料留在受保護環境。
6. 新增功能若對首發沒有必要性，先列後續。背景／原生通知延續既定 iOS 規劃，依首發需求安排時段與權限，不作為這輪 Windows 核心驗收的額外前置。
