## 1. 目的與本輪邊界

在現有能力上，讓品牌攤商更容易完成三件事：記得報名哪些市集、確認繳費、記下每場營業成果。延伸功能應協助這三件事，避免讓使用者先理解整套管理系統才能開始記錄。

使用者本輪授權為實際操作、體驗分析、完整規劃及共同討論；不是全面重做介面或實作授權。本輪只新增本計畫、操作證據及既有驗收文件的索引。未保存場次、繳費、成交、盤點、心得、商品、團隊或訂閱變更；只瀏覽、切換、開啟／關閉空白或既有資料表單，未提交。未檢視或修改 Demo，未操作測試救援工具。沒有新增背景通知、付款、後台或 ERP 範圍。

本輪基準是 HEAD `775a276` **加上工作區既有未提交變更**，不能只用提交編號重現。測的是 `http://localhost:3000` 正式 App 本機程式、已登入普通測試老闆帳號。這不代表線上部署相同，也不代表 iOS／Android 實機完成驗收。

先前已完成的修正以 [手機完整流程紀錄](MOBILE_MARKET_FLOW_REVIEW_2026_10_25.md) 為準；本計畫不將那些項目重新列成未實作。背景／原生通知依決策留到正式 iOS 開發。

## 3. 整體判斷

功能已足夠支撐完整出攤循環。主要問題是**次要資訊占據主要操作位置、同一件事情有不同名稱、不同功能重新選日期／搜尋，以及管理入口的位置不符合預期**。不需要先刪掉現金、心得或分析，也不需要全面新增精靈。

### 3.1 應保留的現有優點

1. 五個主導覽「今日／市集／商品／分析／更多」已形成穩定架構，暫不全面改名或增加第六個頁籤。
2. 首頁待繳費／待錄取方塊、進入現場的明確按鈕，以及清單搜尋／返回保留應繼續使用。
3. 市集以「現場／回顧／管理」分工，回顧六入口已改成選定才顯示；不回到一次堆滿所有卡片。
4. 快速收款與商品銷售可直接開啟，不必先切換另一層交易方式。
5. 市集表單已有基本／選填分組及固定保存頁尾；不把已存在的設計再當成新功能。
6. 不記錄現金、略過心得，仍可正常營業和收攤；不得改成必填步驟。
7. 心得另建待辦已收進更多操作，不自動挑下一場、不公開整篇心得。
8. 報表與分析已有資料不足、來源完整度提示；精簡排版時應保留必要的判斷邊界。

### 3.2 設計準則

- 手機先提供一個當下主動作；桌面提高比較密度，兩端共用資料與規則。
- 精簡以減少尋找、重複輸入及不必要選擇為目標，不以最少點擊數作唯一指標。
- 同一份資料可以有情境捷徑，但不建立第二套 writer、不同金額算法或不同權限。
- 可選功能不常駐完整表單；已輸入、未同步、衝突及有問題的狀態不得因收合而消失。
- 低頻說明漸進揭露；付款分類、日期、金額、未同步及短少／溢收等影響判斷的資訊仍直接可見。

## 5. 可以整合什麼，以及不應合併什麼

| 可以整合的層級 | 具體整合 | 必須保留的差異 |
| --- | --- | --- |
| 出攤準備入口 | 待辦、準備範本、主辦資訊放同一準備工作區，依階段排序 | 範本不是已完成待辦；套用仍有明確確認與防重複 |
| 現場商品查找 | 管理頁與銷售頁共用商品搜尋／分類規則 | 現場只選商品／數量；管理編輯與財務資料不跟著開放 |
| 現金盤點閱讀 | 開攤、收攤、現金比較共用日期及來源狀態，分基本／進階 | 現金盤點、成交營收、現金差額仍是不同概念與資料 |
| 心得回顧 | 單場與集中頁共用卡片、編輯器、私人標示與更多操作 | 集中頁不變成待辦管理；整場與單日範圍不同 |
| 分析與報告 | 共用範圍描述、資料不足原因與結果模型，報告作輸出入口 | 場次集合與期間統計不可默默互換；PDF 不等於另一套算法 |
| 市集工具 | 固定安排、心得、縣市整理有一致工具入口 | 不把低頻工具加入底部主導覽；不新增獨立全域待辦中心 |
| 系統狀態 | 統一提示詞、圖示、問題詳情入口 | 草稿、本機待同步、已同步不合併成單一「已儲存」 |

**不建議的簡化**：把報名、繳費、營業、收攤合成一個狀態；把主辦備註、交接筆記、私人心得合成一欄；移除所有確認；以自動同步取代私人編輯器的明確雲端保存；強制收攤盤點／心得；把兩種收款先藏在一個新選擇頁。

- 數值採一致幣別與位數規則；不可用四捨五入隱藏對帳差額。時間畫面統一 HH:mm，保存及比較仍沿原契約。
- 載入保留場次標題與當前任務，不以全頁空白或錯誤的「0筆」取代尚未完成的載入；正式效能需 production build 再量測。

### 6.4 平板／桌面

- 共用流程與結果模型，增加左右分欄：例如場次清單＋詳情、商品列表＋編輯、心得篩選側欄＋內容。

- 表格、比較與報表以桌面優先提高資訊密度；保留觸控及鍵盤操作，不依賴 hover。
- 在1024平板直橫向及1440桌面檢查捲輪、彈窗焦點、Sticky 區與返回位置；本輪只補看1440首頁，未宣稱這些均已驗證。

## 9. 驗收矩陣與保護既有功能

### 9.1 情境

| 使用者／資料 | 必測任務 |
| --- | --- |
| 新手、零場次、零商品 | 直接新增第一場，基本資料建立即可；不被全套設定或付費牆擋住已允許的功能 |
| 一人品牌、只記總收入 | 報名／繳費→快速現金收入→收攤；全程不必開庫存、互動、照片、盤點或心得 |
| 多商品品牌 | 7／50／200項的本機合成商品量；搜尋、分類、數量修改、付款與提交；不將合成量寫入營運帳號 |
| 每週固定品牌 | 建立／找固定安排，單日略過、暫停與未來縣市影響範圍清楚 |
| 多日、同日多場 | 明確當前場次與營業日；當天收攤不代表整場完成；現金盒共用警告可見 |
| 有心得／長文／篩選 | 首屏先有內容、有效篩選可見、全文可讀、整場／單日不混淆、原稿可恢復 |
| Team老闆與各員工角色 | 依真實權限顯示入口及說明；私人心得、盤點與敏感財務不因整合而外露 |
| 網路中斷／雲端錯誤 | 已保存、待同步、草稿、讀取失敗不混為一談；不重複成交、不丟草稿 |

### 9.2 判定方式

- 360／390／430手機、1024平板與1440桌面；除表格有明示容器外，沒有文件橫向溢出。
- 手機主要按鈕可觸及、與底部導覽不重疊；打開真機軟鍵盤後仍可看清輸入與下一步。
- 核對畫面標籤、焦點、閱讀順序、放大文字和狀態提示；不把開發工具按鈕列為產品問題。
- 記錄指定任務的導航點擊、捲動與首次理解結果；S2以可控商品量衡量查找，不先宣稱速度提升百分比。
- 財務／庫存：UI 修改前後，以同一隔離測試場次核對交易、營收、付款分類、庫存、盤點與差額不變；若任務需要保存，明確記錄新增事件。
- 草稿／隱私：未保存離開、切換場次、帳號切換、同步延遲、版本衝突都不靜默覆寫；日後保存方式若變更需另切片。
- 批次：過期預覽、防重複、略過過去／取消／已有營運資料的既有規則完整保留。
- 驗收通過才整理選定變更提交；工作區現有 Demo／素材／其他變更不納入；部署後另驗，不以 push 或 build 代替。

## 11. 建議共同討論的三個決策

1. **付款方式**：建議每筆預設現金，其他付款只作用於當筆；替代方案是保留最近選擇，但明示「沿用上筆」。前者更符合既有現金優先需求，也較不容易誤分類。
2. **新增入口**：建議主新增直接到單次市集，固定安排有清楚次入口；替代方案保留現有兩種營業選擇，但將固定管理移出新增對話框。先不更名整個市集主導覽。
3. **第一批範圍**：建議先做首頁／狀態語意／權限文案與現場商品查找；替代方案先做心得內容優先與回顧減負。均不建議同時全面換視覺風格和頁面架構。

可逐項調整，不需一次同意全部18項。收到方向後，再把第一批轉為具體實作清單與前後驗收。
