# 市集三分頁功能位置檢視與修正

日期：2026-10-26（Asia/Taipei）。範圍：老闆市集工作台的「現場／回顧／管理」，以手機優先完成實作與畫面複驗。沒有操作 Demo、修改營運資料或變更訂閱／角色權限。

## 調整原則

- **現場**：今天的時程、當下營業操作、收款、互動、現金盤點、場地資訊與交接待辦。
- **回顧**：收入與成交成果、已保存現金、心得、顧客互動分析、成交照片與成本設備。
- **管理**：報名／繳費、期限提醒、是否要求成交照片、場次成本及取消／刪除。場次內容仍由原有編輯表單維護。

以同一份資料與既有動作調整入口，不新增另一套時程或營業狀態。

## 已完成修正

| 功能 | 原位置／問題 | 修正後 |
| --- | --- | --- |
| 今日時間軸 | 放在管理下方，現場需要的報到與營業時程必須切頁找 | 移至現場，準備時預設展開，營業中與已收攤首次開啟預設收起；收起仍顯示營業區間 |
| 提前開始／今日收攤 | 收攤主入口只在管理；時程與今日動作分散 | 由現場呼叫原有 `MarketOperatingSessionControl`，保留原時段、角色就緒、更新鎖定與二次確認條件 |
| 營業時段規則 | 管理另有「今日現場模式」整張說明卡 | 合併到時間軸的說明按鈕，點開可看自動開放、延長與多日場次規則 |
| 主辦／場地備註 | 現場工作及管理各顯示同一份唯讀內容 | 移除管理的重複展示；現場工作保留原內容，編輯表單仍可維護 |
| 修改時間 | 只有畫面上方編輯按鈕及長句操作指示 | 時間軸內新增「修改時間」／空狀態「設定時間」，開啟原編輯表單；時間軸欄位仍在原表單分組，沒有另建保存流程 |
| 時程標籤與時長 | 時程內寫「營業中」易與即時狀態混淆；提前進場／報到固定標示 30m | 改為「開始營業／結束營業」時間點；移除無實際時差依據的固定 30m，時長仍讀原共用格式 helper |

目前現場順序依準備／營業中／已收攤安排，詳見本文最後一節。今日營業操作已整合到頂端摘要，不再另外顯示狀態卡。

## 檢視後保留的位置

- 成交照片的「是否要求」屬於管理設定；成交照片內容與歷史仍在回顧，待補入口仍在現場。沒有把設定開關與相簿混成同一個功能。
- 報名繳費及期限仍在管理；現場未開放時保留前往管理的具名入口，讓使用者能處理報名／時間設定。
- 成本明細在管理供確認場次設定，也在回顧成本設備供對照成果；是同一份資料的兩種情境，不另存副本。
- 心得、歷史成交、互動分析維持回顧。現場交接筆記與待辦維持現場，收攤後沿用既有唯讀規則。
- 這次只調整上述三分頁。員工是另一套「現場／紀錄／工作」介面，本輪沒有搬動其功能或擴大員工權限；相關回歸檢查仍執行。

## 程式與跨平台邊界

- 新增 [MarketTodayTimeline](../components/markets/MarketTodayTimeline.tsx)，只讀共享 `Market` 時間欄位、共享格式與時長 helper，React state 僅控制展開。沒有直接呼叫 `window`、`document`、儲存、裝置或原生 API。
- [MarketDetailScreen](../components/markets/MarketDetailScreen.tsx) 將時間軸、當日營業操作與選填現金放在 `live` 條件內；原本營業中／非營業中兩個現金呼叫分支整合成現場的單一入口。
- 原 `handleStartEarlyOperation`／`handleCloseTodayOperation`、`MarketOperatingSessionControl`、時段判斷、資料模型、RPC 與事件同步皆未變更。編輯入口沿用原 `handleOpenEditForm`。
- 管理刪除、報名、照片要求等動作仍沿用既有保護；沒有 SQL migration、雲端設定、CORS 或付費方案變更。

## 第二輪：現場內容的優先順序與頂端狀態整合

依使用者後續要求實作。目的是讓使用者先看見當下要做的事，收攤後仍能找到補登與盤點，不必從重複說明中找入口。

| 情境 | 頂端摘要／操作 | 摘要下方的實際 DOM 順序 |
| --- | --- | --- |
| 準備中 | 狀態、營業區間、原有時段說明；可提前開始時提供原動作，其餘提供「查看市集管理」。移除無交易時的收入 0／成交 0；有待補、讀取中或待確認的照片仍顯示 | 今日時間軸（預設展開）→ 現場工作（手機預設展開）→ 開／收攤現金（選填、預設收起） |
| 營業中 | 收入、成交、待補照片；原本的收攤動作整合至摘要下緣，仍需二次確認。一般營業時省略重述狀態的長句；提前／延長等特殊說明保留 | 收款 → 記錄互動 → 最近紀錄 → 現場工作（手機預設收起）→ 選填現金 → 時間軸（預設收起）。桌面保留原交易／互動／紀錄分欄 |
| 今日已收攤／場次已結束 | 只保留一個狀態標題；原「今日現場操作已關閉；遺漏收入請改用補登收入。」直接放在摘要。提供「補登收入」與「查看回顧」 | 選填現金 → 現場工作（手機預設收起）→ 時間軸（預設收起） |

待補照片仍在摘要提供具名可點入口，不會因收起其他區塊而隱藏未完成工作。現金仍可完全不記錄，不會因排序前移自動要求填寫或儲存。盤點補充說明改用可點資訊圖示，讀屏名稱仍為「查看盤點說明」，最小觸控區 44px；360px 畫面已確認標題不再擠成兩行。

### 狀態與資料邊界

- 新增 `lib/markets/market-live-presentation.ts`，只將既有 canonical session 分類供排版，不改變可收款、可提前開始、可收攤的判斷。多日市集今天手動收攤後，即使整體 `workspacePhase` 因未來日期仍為準備中，也按 `session.phase === 'closed'` 顯示今日已收攤；不會重新開放現場交易。今日時段自然結束而 canonical session 已指向下次安排時，仍跟隨該狀態。
- 補登沿用既有 `handleOpenAddRevenue`／`AddRevenueDialog`，優先使用有效且非未來的 session 日期，否則取最近已到的營業日期；沒有可用日期時不顯示捷徑。資料庫不可用時原頁面錯誤 guard 與原 handler 仍會阻止操作。沒有自動新增收入。
- 角色未就緒不提供補登／提前開始／收攤動作，沿用原 owner 控制條件。員工仍使用原狀態卡與既有權限，沒有新增員工收攤權限。
- `MarketLiveLayout` 用有穩定 key 的區塊安排真正 DOM 順序，讀屏與鍵盤順序一致，不以 CSS order 假搬動。折疊值是首次開啟預設；使用者當次展開／收起選擇不會因時鐘自然跨階段而強制重設，避免打斷操作。
- 現場工作仍沿用原完成場次的唯讀保護；多日場次若後續仍有安排，其既有編輯範圍不因排版變動而擴大或縮減。
- 新增 `MarketLiveLayout`／`MarketLiveSummaryActions`，摘要支援補充說明與操作插槽；原營業控制新增 embedded 呈現模式，標準員工卡片保留原外觀與文案。新程式沒有裝置 API、原生依賴、同步或 SQL 變更。
