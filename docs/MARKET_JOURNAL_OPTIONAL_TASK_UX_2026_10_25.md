# 出攤心得與選用待辦：體驗需求調整

日期：2026-10-25（Asia/Taipei）。依使用者對學習成本的疑慮，調整既有 UX-NEXT-02B；沿用已完成的 081 保存契約。

## 產品定位與優先順序

出攤心得的核心價值是快速留下感受、方便日後回顧。使用者寫完「這場很喜歡」就已完成一個完整操作，不需要接著整理行動計畫。

| 層級 | 使用者目的 | 本次需求 |
| --- | --- | --- |
| 核心 | 記下人潮、停車、場地感受與心得 | 逐場寫入、保存、閱讀／修改；保留既有草稿與衝突保護 |
| 核心 | 日後找回經驗 | 集中心得頁、日期區間、縣市與關鍵字篩選 |
| 次要選用 | 已明確知道有一件事需要在某場執行 | 從單篇「更多操作」另建出攤待辦；不占主要操作列 |
| 後續評估 | 再去同一場地前回看過往心得 | 留待使用者需求與可靠場地辨識方式確認；自由輸入地點或相同縣市不足以自動判斷同場地 |

功能優先順序不由已完成的程式量決定。選用待辦不作為心得完整度、首次上手、付費價值或正式發布的必要條件。

## 主流程

1. 使用者在市集內寫心得，保存後回到原本的心得區。
   2026-10-25 手機整合調整：單場入口為「回顧 → 出攤心得」，選定後才讀心得，不預先擠在每日表現之前。編輯時同一篇不在下方重複列出；見 [手機流程驗收](MOBILE_MARKET_FLOW_REVIEW_2026_10_25.md)。
2. 心得卡主要操作為「閱讀／修改」，集中頁另有「回到原市集」。
3. 「更多操作」預設收合，包含「另建出攤待辦」與「移除心得」。入口未啟用時不顯示準備中按鈕。
4. 保存心得後不彈出待辦視窗、不要求填下一場、不自動建立或複製事項，也不增加「未整理」標記或催促。

## 選用流程

- 名稱採「另建出攤待辦」，說明原心得完整保留，避免「轉成」被誤解為搬移、刪除或替換。
- 打開後以「要記得的事」為第一個輸入，可直接寫一件準備事項；每行一項。
- 目標場次由使用者明確選擇，沒有預設「下一場」。提示停車、進場時間等經驗可能只適用原來的場地。
- 「從心得原文挑選（選用）」預設收合；需要時再展開。文字預設全不勾選，勾選後可改寫，收合時顯示已選數量，避免隱藏選擇造成意外加入。
- 填入文字或勾選原文且選定場次後，才開放預覽。保留兩個階段：整理內容／選場次 → 預覽目標與全部文字 → 明確確認加入。
- 原心得為私人；若目標場有員工協作，另建的普通待辦沿既有 Team 權限分享。只有確認的文字送出，不附心得全文或私人來源連結。
- 關閉視窗不建立待辦；未確認的輸入與勾選不保存，畫面先行說明。原心得和既有待辦不受關閉影響。
- 沒有可用場次時提供原因，仍可回顧心得；不強迫先建市集或完成此流程。

## 實作邊界

本次為介面層級、文案與入口顯示調整。共用文字／日期／權限驗證、081 RPC、回條冪等、來源版本檢查及同步方式沿用既有實作。沒有新增瀏覽器／裝置能力、套件依賴、migration、訂閱能力或原生通知；可由 Web／iOS／Android 共用。

既有心得及已另建的普通待辦保留。未來若需要暫停選用功能，可關閉既有 `NEXT_PUBLIC_JOURNAL_TASKS_ENABLED`，心得入口會隱藏另建操作，已建立的待辦仍沿普通待辦使用。

## 驗收條件

- 未展開更多操作時，畫面不顯示另建或移除按鈕；閱讀／修改可直接操作。
- 鍵盤和手機觸控皆可展開更多操作與原文挑選；不依賴 hover。
- 直接填一項即可預覽，不必勾選心得原文；原文收合時的勾選數量正確。
- 取消預覽／關閉後回到心得；重新打開沒有殘留未確認的輸入與選擇。
- 手機尺寸沒有橫向溢出；私密性與目標確認文字可閱讀。
- 既有共用／保存測試、手機型別與受影響 ESLint 通過。變更不涉及雲端契約，沿用 081 已完成的真實保存與隔離 SQL 證據。
