## 驗證故事與資料範圍

付費老闆在合成測試場次核對每日銷售成本，經由既有 094 RPC 保存與讀回，再在列表、單場、分析、報告與 PDF 看見一致結果；撤回核對後不把未知成本顯示為確定利潤。

僅使用既有 `[配色驗收1030] 收款與回顧`（`93f96c9b-f036-498a-9046-3dddb981acbb`），營業日 2026-10-30、收入 50、成交 1 筆、攤位費 100。核對歷程為原成本確認 0 → 10 → 撤回 → 恢復 0；最後已重新載入確認恢復。沒有新增／刪除成交、商品、庫存或照片，只有這個測試場次的核對歷程追加。

## 本輪發現與修正

撤回核對後，上方淨利與列表已正確顯示待確認，但每日明細仍直接顯示銷售利潤 50。這會讓同一畫面對成本完整度的說法不一致。

- `financial-record-quality.ts` 新增 `isDailySalesProfitUsable`，報告與每日卡片共用日成本的可信條件。
- `DailyRevenueStats.tsx` 接收可信、來源相符的日確認；未確認零成本、待同步、舊確認失效與同日重複來源顯示「待核對」，每日合計亦維持相同狀態。
- `MarketDetailScreen.tsx` 傳入既有 owner overlay 的日確認。員工 `hideProfit` 不新增成本讀取或利潤呈現。
- 新增實際 React 渲染回歸 `tests/daily-revenue-financial-quality.test.tsx`，並加入 manifest；不是只比對按鈕或原始碼字串。

最終檢查：本輪 15 個相關測試檔、修改檔 ESLint、mobile TypeScript、Web production build、mobile static build 與 35 項 segment aliases 均通過。沒有宣稱 repo 全測試或全部角色／裝置已通過。
