# 基礎出攤流程強化與驗證紀錄

日期：2026-10-20（Asia/Taipei）

## 使用者目標與範圍

核心用途依序為：記得報名哪些市集、確認是否已繳費、記錄每場營業額。
以手機操作為主要設計與驗證環境，Web 同時維持平板與電腦的可讀性。
本輪只強化既有資料的呈現、搜尋與導覽，不增加付款、訂閱或財務寫入流程。

依使用者後續要求，`/demo` 不作為正式版設計或功能驗收依據；本輪未修改既有 Demo 原始碼。
工作區原先的 Demo、Demo 測試與素材變更均保留。

## 正式版實際觀察

來源為已登入的 `https://markit-app-mocha.vercel.app/`，以 390 × 844 手機版面查看。
僅瀏覽首頁、市集清單、既有市集管理及回顧，未變更正式帳號的場次、繳費或成交紀錄。

| 觀察 | 對使用者的影響 | 本輪處理 |
| --- | --- | --- |
| 首頁已有近期場次，卻沒有報名／待繳費摘要 | 必須進清單並另外篩選，才知道還有事情待處理 | 加入老闆專用報名與出攤準備區塊 |

| 近期安排存在同日多場 | 需要自行對照日期及確認分工 | 加入非阻擋的同日安排提示 |

## 實作內容

### 首頁與報名入口

- 在首頁顯示待準備場次中「待繳費」與「等待錄取」的數量及近期兩筆場次。
- 摘要只依既有報名狀態整理，不代表已查核銀行或主辦單位的付款狀態。
- 點選場次直達管理頁；點選群組進入對應的市集篩選結果。
- 首頁入口會清除先前搜尋，避免新入口受到舊篩選條件干擾。
- 近期市集明示等待錄取、待繳費、已繳費或固定營業等狀態。
- 「如期舉行」不推定為已有繳費紀錄。
- 員工不會載入或顯示新增的老闆準備摘要。

### 搜尋與返回

- 名稱及地點支援多關鍵字、大小寫與全半形正規化。
- 搜尋結果數同步反映於階段頁籤及報名進度篩選。
- 顯示目前分類結果數；無結果時可清除或切換分類，不會把資料誤當成不存在。
- 搜尋輸入使用 16px 字體與至少 48px 高度；清除按鈕為 48px 觸控區。
- 返回清單時保留搜尋、階段、報名篩選及原有捲動位置。
- 真正登入後的流程驗證找出並修正兩項問題：初始化時的清理程序會覆寫已儲存的搜尋／分類；切換詳情載入畫面後才儲存位置會把捲動誤記為 0。現在於初始狀態讀入還原值，僅在資料可用時保存，並於切換載入畫面前捕捉位置，避免導覽卸載覆寫。
- 詳情返回按鈕的輔助名稱改為「返回上一頁」，符合從首頁或清單進入時的實際行為。
- 透過 `SessionStatePort` 儲存暫時的介面狀態，Web 存取隔離於 `lib/platform/web`。
- 儲存空間拒絕存取時，搜尋與導覽不會因此丟出錯誤；僅可能無法恢復上次位置。

### 同日安排

- 只考慮仍可見、尚未結束且未取消／延期的場次。
- 明確使用實際選取的多日日期，不把不連續日期之間的空檔當成出攤日。
- 相容舊資料只有起訖日期的情況；不以 UTC 轉換本機出攤日期。
- 同一對場次只提示下一個共同日期；首頁最多展示前三個日期群組。
- 提示不會禁止報名、取消場次、判定時間衝突或自動改變團隊分工。

| 舊搜尋 → 首頁 → 報名入口 | 先搜尋歷史市集地點，再從首頁進等待錄取；舊條件清除，正確顯示 1 場 |

| 無結果與清除 | 不存在的關鍵字顯示 0 場與清除入口；清除後原清單恢復 |
| 等待錄取搜尋 → 詳情 → 返回 | 修正後保留「高雄」、待準備及等待錄取；不再跳到已結束 |

| 長清單 → 詳情 → 返回 | 修正後前後捲動位置同為約 1,871.2px |
| 首頁場次 → 管理 | 直接開啟 `task=registration`，管理分頁為選取狀態；返回回到原首頁 |

## 2026-10-21：採用提醒方塊

使用者選擇「提醒方塊」方案後，正式首頁改為兩個並排入口：待繳費、待錄取。
整格可點擊，直接進入既有市集清單的對應報名篩選；數量沿用共用規則與帳號資料，沒有寫死數字。
單項為零時保留淡化且停用的格子，兩項皆為零時顯示「目前沒有待處理報名」。

同日多場由報名摘要拆成獨立區塊，移至近期市集下方，以原生可操作的 details/summary 預設收合。
摘要顯示最近日期與場數；展開後顯示目前模型提供的所有日期群組與報名狀態，
不再截斷為前三組。每筆可進入市集管理。今日若也有同日多場，營運重點區保留一行安排提醒。
