# 手機操作優化：收款、返回、回顧與提示

日期：2026-10-26（Asia/Taipei）。本輪依使用者同意的六項優化實作，另修正首頁待補照片初始化缺口。這是本機程式與驗收紀錄；本輪沒有 commit、push 或部署。商品搜尋／分類不在本輪範圍。

## 完成內容

| 項目 | 實作與使用者結果 | 邊界 |
| --- | --- | --- |
| 估計淨利 | 單場摘要、管理固定成本、成本總計改用既有共用財務 helper；補列報名費、桌布租金，提供「淨利怎麼算」 | 只統一顯示，不重寫歷史收入／利潤。不能據此判定過去所有金額都有錯 |
| 每筆付款方式 | 新面板預設現金；成功成交後重設現金；確認按鈕直接顯示金額和付款方式 | 失敗時不執行成功重設，保留同筆輸入與選擇；不將未成功寫入說成已排隊 |
| 商品管理返回 | 商品清單、商品明細都有「返回原場次銷售」，保留安全的來源與返回目的地；回到原場次直接開商品銷售 | 不跨頁保存購物車；離開前顯示需重新選取。來源參數不是權限，未開攤／已收攤與員工規則仍生效 |
| 現金回顧 | 選「現金紀錄」後直接顯示工作區，移除額外外層折疊；現場選填卡仍可收合 | 保存、草稿、雲端來源、差額限制與錯誤警示保留 |
| 空心得 | 單場顯示「這場市集還沒有心得；想記下什麼時，再按『寫心得』」 | 集中頁及篩選無結果保留各自情境，不要求使用者整理待辦 |
| 提示分層 | 照片長說明改原地展開，結算 PDF 說明改具名說明入口；方案文案去除技術詞，升級提示按鈕至少 44px | 金額、角色、付費資格、未開放購買與資料品質限制仍直接可見；不改商業規則 |

### 財務口徑

沿用 `lib/analytics/market-financial-summary.ts`，本輪沒有新增另一套財務模型：

- 固定成本＝報名費＋攤位費＋自付桌／椅／傘／桌布租金。免費提供的設備不扣款。
- 估計淨利＝已記錄銷售利潤－固定成本－營收抽成。
- 明確記錄利潤為 0 時維持 0；缺少利潤時才暫以營收估算。
- 可退保證金不列成本；交通、人工等未記錄支出不會自動計入；現金盤點不改變淨利。

## 首頁照片提醒的修正

原首頁只讀本機待補佇列，從雲端成交重建提醒的邏輯位於單場頁；同一資料庫不代表不同瀏覽器有相同本機佇列。首頁現在於授權與紀錄同步完成後，針對今日場次重用既有 owner recovery，讀取成交／雲端照片狀態並重建本機提醒。

- `lib/sales/home-photo-reminders.ts`：去重場次，每批最多 3 個平行讀取；彙整已上傳隱藏名單、舊資料不明數與部分失敗。
- `hooks/useHomePhotoReminders.ts`：綁定 actor／owner／場次範圍，處理成交晚於市集載入、同步更新、離線、存取拒絕及重試。存取拒絕時不顯示該結果。
- owner 才可重建；員工只讀自己的既有本機工作，不取得 owner recovery 權限。照片執行旗標仍生效。
- 未確認時顯示狀態，不將空清單誤稱為全部完成。已上傳照片可從提醒隱藏，不刪本機原圖。
- 沒有新增上傳、照片 claim、雲端修補、事件寫入、圖片刪除或自動重送 worker。

待補提醒可重建，尚未上傳的原圖仍只在來源裝置。照片彈層內採 `<details>` 原地展開，避免再疊一個說明視窗而被既有彈層遮住。單場待補清單已確認兩筆的說明展開／關閉與返回。

### 驗收限制與後續

本輪未強迫資料庫寫入失敗；同筆失敗保留依成功／catch 分支與針對性回歸檢查，不能冒稱已實測雲端中斷。乾淨瀏覽器首次登入、完整離線／跨裝置照片、真實員工帳號與原生手勢仍需獨立驗收；付費 PDF 分支沿用權限與模型測試，沒有為查看頁面變更帳號方案。

沒有 SQL migration、環境旗標、價格、席次、付費資格、原生商店或購買流程變更。既有 Demo／素材修改不是本輪產出，保留原狀。正式版本須提交、推送並完成部署後，再驗收同一批行為。
