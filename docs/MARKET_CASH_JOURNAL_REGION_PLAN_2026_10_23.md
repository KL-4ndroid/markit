## 3. 開攤／收攤現金：預設不記錄

### 3.1 最小操作與狀態

- 每個場次營業日提供「不記錄」（預設）、「直接填總額」、「依面額計算」三個選擇，不在開攤／收攤時強制彈出必填流程。
- 不記錄時不需要金額；已輸入零元表示確實記錄為 0，與未記錄不同。不把選單預設的不記錄當成已儲存盤點。
- 每日進入新場次仍預設不記錄，不自動沿用昨日金額、面額數量或記錄選擇。昨日收攤數字只有使用者主動選擇帶入後才成為今日草稿，儲存前仍可確認。
- 開攤與收攤可各自記錄、略過、稍後補寫或更正；只有一邊有金額時保存已有內容，提示尚無法比較，不推定另一邊是零。
- 多日市集按既有營業日期識別保存，跨午夜使用所屬營業場次日期；同日多場各自保存，不自動把同一現金盒視為可重複分配的資金。

### 3.2 總額與面額明細

- 總額模式只需填入金額；詳細模式的基礎面額為使用者指定的 1,000、100、50、10、5、1 元，數量為張數／枚數。
- 建議同列補上常用 500 元欄位；其他面額可日後收合擴充，總額模式仍能記錄任意有效金額，不要求用戶把所有現金拆成既定面額。
- 詳細總額 = 各面額 × 數量的合計，邊填邊顯示。數量須為非負整數，空格視為該面額未填；儲存為詳細紀錄時需有明確輸入／確認，不能無操作就生成零元盤點。
- 詳細模式的總額由明細推導，不同時保留一個能與明細矛盾的可編輯總額。換成總額模式可帶入已算出的總額；總額換詳細時不虛構面額分配，也不把兩種輸入加總。
- 模式切換或選不記錄前，已填但未儲存內容可提示保留草稿；重新開啟既有紀錄以已儲存內容為準，不能被初始預設覆寫。

### 3.3 最基本的比較方式

開攤現金包含準備找零的資金；收攤現金指同一計算範圍內實際留下的全部現金，包含當日收進的現金。標示盤點應在收攤提領／存款之前，或另記提領，避免兩個時間點口徑不同。

- 現金增加額 = 收攤現金 − 開攤現金。這不是總營收，也不是淨利。
- 若沒有額外現金進出：預期收攤現金 = 開攤現金 + 該日已記錄的現金銷售。
- 若使用者需要，可展開一個簡單「其他現金進出」淨額與備註；正值為補入，負值為拿出／現金支出／退現等，避免建立專業帳簿。完整式：預期收攤現金 = 開攤現金 + 現金銷售 + 其他現金進出淨額。
- 現金差額 = 實際收攤現金 − 預期收攤現金；正值表示多出、負值表示短少。非現金收款不進此比較，商品成本也不直接從現金盒扣除。
- 未記額外進出時以「假設沒有其他現金進出」標示比較依據；可直接留下差額備註，不要求填完整資金流才能保存。
- 缺任一盤點、已知付款分類不完整、來源資料未同步核對或同一現金盒橫跨多場而未拆分時，不顯示無條件的「已對平」。允許保留盤點總額與待確認提示。
- 差額不自動產生收入、更改成交、庫存或估計淨利。補登／撤回成交、改付款方式或更正盤點後，重新計算並標示原核對基準已更新。

例：開攤 2,000、現金銷售 3,500、非現金銷售 1,000，無其他進出時預期收攤 5,500；實盤 5,450 則差額為 −50。當日已記錄營收仍為 4,500，不是收攤現金 5,450，也不是現金增加額 3,450。

## 4. 出攤心得：逐場與集中檢視同一份資料

- 心得仍歸屬原 market／owner，可選某個營業日或整場總結，保存作者、建立及修改時間；單場頁與彙整頁共用識別與資料，不做手動複製或雙份同步。
- 手機建議先在市集區提供「出攤心得」入口，Web 可提供較寬的心得清單；第一版不擠入新的固定底部分頁，確切導覽位置於畫面切片驗收。
- 清單顯示市集名稱、出攤日期、縣市／自由地點、心得摘要，點入可看全文、修改並返回原場次；依出攤日期排序，修改時間另外顯示。
- 支援關鍵字、日期與縣市篩選；多篇同場心得仍顯示各自日期。零篇時引導查看已結束市集，不要求補完所有歷史。
- 內容保留個人感受與主觀觀察，不以營收自動生成感想或公開評價；不自動提供給主辦、其他品牌或員工。
- 彙整讀取也要通過相同 owner 與角色授權，不能因彙整就讀到更多工作空間資料。第一版沿用品牌主私人心得的建議範圍，團隊共用另定政策。
- 已結束場次正常可讀其心得；市集刪除／封存的心得保留與可見性需明確設計，不能依名字重新掛到另一個市集，也不能因彙整索引留下未授權或已刪內容。

## 5. 縣市欄位與地區分析

### 5.1 地點維持自由輸入

- 新增獨立 `regionCode` 欄位，選項涵蓋直轄市、縣市與離島，以穩定代碼保存、統一顯示名稱；「台／臺」別名只用於輸入輔助，不生成兩個統計群組。
- 原 `location` 繼續保存「台南南紡」「台南市東區東平路12巷7號」「台北松山捷運旁」等使用者文字，不強制標準地址，也不要求 GPS 或地圖 API。
- 建議新增場次時將縣市放在地點前方，允許稍後補填；空值顯示「未分類」，不預設為使用者居住地或上一場縣市。文字有明確線索時可提出建議，但保存／批次補填前要確認。
- 地點與所選縣市看似不符時可提示檢查，不自動改寫任一欄；「新竹」「嘉義」等不完整線索不能直接決定是市或縣。
- 舊市集維持原狀，不因升級變成無效；提供未分類清單和可預覽的多筆補填，僅更新使用者確認的範圍，保留原地點與更新依據。

### 5.2 固定營業與歷史範圍

- 手動場次及固定營業都須能保存縣市；Venue 可有預設縣市，產生新場次時複製為該場快照。
- 更改 Venue／排程預設只影響允許更新的未來場次，不自動改歷史已發生場次的分析歸屬。單場覆寫保留自己的縣市。
- 補填或更正某場縣市後，該場的地區分析重新歸類，不重建成交或複製日統計；顯示新分類的資料時間，舊名額／金額不重複計入。
- 新心得／盤點屬於場次使用者活動；固定營業排程的保護條件需納入它們，避免排程調整覆寫已有紀錄的場次。

### 5.3 地區分析第一版

| 指標 | 計算範圍與避免誤解 |
| --- | --- |
| 已記錄營收 | 篩選期間內該縣市的有效收入合計，排除已撤回交易，不含開攤／收攤現金或現金差額 |
| 市集場次數 | 依唯一 market ID 計數，多日同一場仍為一場；報名／取消與實際出攤的狀態分開，不能把報名都算成已出攤 |
| 出攤天數 | 以 market ID + 營業日期去重，同日兩場為兩個場次日；若要呈現曆日天數需另命名，不混成一個指標 |
| 單日平均營收 | 使用同一已核實營業日範圍的收入與分母；不把沒有收入紀錄的未來排程當成零營收，也不把未確認是否營業的缺值當成已休息 |
| 商品表現 | 只用具商品明細的有效成交彙總數量／收入，標示明細覆蓋度；純金額補登不虛構商品或售出數量 |
| 未分類 | 未填縣市場次及其收入另外列示，仍保留在整體總額；顯示分類覆蓋度，讓用戶知道地區比較是否完整 |

實際是否出攤的依據需在資料模型中明確定義；若舊資料只能證實有銷售紀錄，先標為「有收入紀錄的場次／日數」，不能假裝已掌握所有零成交出攤日。地區樣本少時顯示原始數據與樣本數，避免直接宣稱某縣市較好賣。

日期範圍沿用既有每日營收規則；跨月多日場次只統計期間內可歸屬的收入。第一版不加入地區淨利排行，以免固定成本跨日分攤及缺成本造成誤導；既有單場估計淨利仍保留。
