# 三方案手機 UI 實際操作巡檢與修正方案

日期：2026-10-26（Asia/Taipei）。狀態：原始巡檢已完成；2026-10-27 已依使用者授權實作三批呈現修正，逐項進度與限制見第 8 節。這份報告是本輪內建瀏覽器觀察，不以先前原始碼盤點代替實際操作。

## 1. 方法、範圍與實際狀態

- 使用使用者指定的內建瀏覽器，本機正式 App `http://127.0.0.1:3000/`，測試帳號 `123@123`；沒有操作 DEMO 或線上正式分頁。
- 經設定頁的「訂閱身分測試」依序操作免費、輕量、高階，再切回原先的免費測試身分。最後仍為免費測試版，切換的四小時期限會重新計算。
- 主要視覺對照為 390×844 CSS 像素；以 DOM clientWidth=390 核對。內建瀏覽器 viewport override 有最小寬度，因此使用其 CDP 裝置尺寸能力達到 390，再於結束時清除裝置模擬並還原 viewport。
- 模擬手機尺寸下指標座標操作未能可靠觸發控制項，改以可存取的鍵盤 Enter／Space 及表單控制操作；不把自動化座標問題列成 App 的觸控錯誤，也不宣稱是真實手機觸控驗收。
- 進入 16 類路由，含同一市集的不同方案／分頁、待錄取、待繳費、今日已收攤等狀態；保留 30 張本機 JPEG 證據。
- 本輪只做閱讀、導航、搜尋、篩選、開啟／取消表單、空表單驗證，以及縣市補填預覽。沒有按下營運資料保存、交易刪除、邀請送出、員工恢復、上傳照片、清除資料或正式付費。
- 現金編輯僅開啟並收起，沒有更動金額或儲存雲端；不要把開啟草稿編輯當成保存驗收。
- 本輪沒有修改 runtime、價格、權限、資料庫或營運紀錄，未 commit／push／部署。

### 重要結論

使用者指出的三項問題均重現。但「尚未開放」必須先分辨原因：免費市集中的這張空卡，是營業時段／報名進度狀態的外框還在，內部操作元件卻沒有內容，不等於有一個尚未開發的功能。解決方式是一起判斷外框與內容是否需要呈現，並修正語意，不能只把所有含「尚未開放」的文字一律刪除。

## 4. 共用呈現規則

| 真正原因 | 正確呈現 | 不應採用 |
| --- | --- | --- |
| 方案不包含 | 正常頁面不呈現該 tab、標題、說明、外框與預留高度；直接網址才提供一次完整解釋與返回 | 每個被隱藏功能都留一張升級或尚未開放卡 |
| 功能尚未推出／rollout 關閉 | 無既有資料且無可用動作時不建立 section；方案頁清楚說明購買／功能狀態 | 留一張空功能卡，或收費文案仍承諾已可使用 |
| 營業狀態未到／已結束 | 摘要說明具體狀態；沒有動作就沒有操作卡，但必要狀態事實仍可見 | 單寫尚未開放、讓使用者以為功能尚未完成 |
| 目前沒有紀錄 | 有價值的功能可保留精簡空狀態＋一個有效下一步 | 多重標題、0 計數、長說明各占一張卡 |
| 樣本不足 | 小型資料需求／進度與有效建議，必要時顯示原始資料 | 使用功能未開放或再升級字眼 |
| 正在載入 | 保持頁面骨架與穩定高度，簡短載入狀態 | 立即顯示錯誤與重試大卡 |
| 權限或網路真的失敗 | 明確說明讀取未完成、保留既有資料／草稿並可重試 | 隱藏成沒有資料、清空紀錄、無限重試 |

判斷應使用同一份 section/view-model，同時決定 **可見性、標題、內容、動作及空狀態**，不要在各子元件隨意 return null，外層卻繼續輸出卡片。既有 API／SQL 權限檢查仍保留，視覺整理不是新的授權來源。

### 免費單場

- 頂部仍保留市集名稱、日期、地點、同步與編輯；營業狀態以共用狀態列／卡呈現，不另外多一張純文字白卡。
- 「安排與準備／出攤心得」兩項分頁可保留，不必為了對齊高階硬補第三個關閉分頁。
- 安排頁依序：報名與繳費整合卡 → 營業操作（真的有動作才出現）→ 本場時間／時間軸 → 主辦備註與個人準備。
- 今日已收攤只保留一處明確狀態；可提供寫心得入口。未來待錄取不顯示空營業卡。未來場次的今日時間軸可改本場時間，日期必要時標在標題旁。
- 已封存且沒有待辦／備註時，收成短摘要或預設折疊；有既有紀錄時保留內容與查看入口。

### 輕量／高階

- 保留現場／回顧／管理既有分工，內容依方案自然組合，不能把沒有的功能補成空位。
- 回顧子分頁使用 5／6 項的明確響應式規則，保留可見焦點與 44px 觸控高度；目前實測是換行排列，不是橫滑被裁切。
- 共用市場頂部、狀態元件、Card、SectionHeader、PageHeader；每個方案的資訊量可以不同，但邊距、圓角、標題層級與互動語言一致。
- 手機主卡內距建議 16px、區塊間距 16px，沿現有 rounded-card／品牌色 token。標題 16px 半粗、狀態／欄位 14px、輔助文字 12–14px；金額用 tabular-nums 與清楚的層級。具體尺寸仍需實作時與現有主題核對，不另創不支援換色的硬白色卡片。
- 只有主要動作使用實心主色；次要查看／編輯用次級樣式。說明入口使用現有具名 ContextHelp，重要繳費／保存／不可逆資訊仍直接可見。
- 日期、貨幣、錄取／繳費狀態用共用 formatter／label resolver。不要在不同方案另外硬寫「已錄取／待繳費」「紀錄／分析」而失去上下文。

## 6. 建議實作順序與驗收

### 第一批：免費基礎版面與空殼

UI-01／02／03／07／08／14：修正共用狀態與卡片、移除無內容 wrapper、合併報名與繳費、調整首頁落地與載入狀態。UI-04 先核對資料責任，不趁 UI 整理重算或搬動費用。

驗收：待錄取／待繳費／今日已收攤三例均無空營業卡；收攤狀態不重複，免費不出現收入／銷售／補登引導；原本編輯、狀態確認、提前開始／收攤與心得入口保持正確。不能以隱藏卡片掩蓋尚未確認的保存能力。

### 第二批：跨方案標題與導覽

UI-05／06／09／10／12／13／15：統一頁名、返回語意、方案與報告用語，五項／六項排版有設計，輕量本月與全部歷史分清。商品照片 UI-11 視 rollout 狀態處理，但正式收費前必須另完成可用性核對。

驗收：免費品牌設定不談成交照片／銷售；輕量不談跨場分析、管理員及 PDF；高階報告不再寫 Pro／Team；目前免費卡不再顯示功能尚未開放。

### 第三批：資料不足與次要內容收斂

UI-16～19：處理進階資料門檻、照片／營收優先、待補與雲端狀態口徑及團隊暫停說明。保留原始資料，不自動恢復員工或重送照片。

### 共通檢查

- 尺寸至少 360／390／430；本輪實測主要為 390，其他尺寸留給實作複驗。
- 截圖對照三方案×等待錄取／待繳費／今日未開攤／營業中／今日已收攤／歷史多日；本輪沒有營業中保存樣本，需另安排隔離測試場次。
- 隱藏最後一個子項時不能留下 section、分隔線或空白 grid 佔位；方案切換時焦點與返回仍有效。
- 每頁標題與 CTA 對應實際落地內容；等待資料與出錯不能混成同一個付款提示。
- UI 測試不替代角色／server／SQL 回歸；不改既有三方案功能、價格、容量及降級資料政策。
